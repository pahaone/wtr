# wtr (windows traceroute) — трассировка маршрута для Windows без прав администратора

[English version](README.md)

Клон [`mtr`](https://github.com/traviscross/mtr) для Windows: интерактивная таблица
потерь и RTT по хопам, режимы отчёта и JSON. Работает **без администратора** и без
сторонних драйверов — на тех же API, что системный `tracert.exe`.

## Сборка

Нужен Go 1.21+ и Windows 10/11 (зависимость одна — `golang.org/x/sys`).

```powershell
go build -o wtr.exe .\cmd\wtr
go test .\cmd\... .\internal\...   # unit-тесты, доступ в сеть не нужен
```

## Быстрый старт

```powershell
.\wtr.exe example.com                    # интерактивная таблица, выход — q
.\wtr.exe -r -c 20 -i 500ms 8.8.8.8      # итоговый отчёт (mtr --report)
.\wtr.exe --json 1.1.1.1                 # машинночитаемый вывод
.\wtr.exe -r -c 5 -a -S 8.8.8.8 8.8.8.8  # с ASN (Team Cymru) через внешний DNS
.\wtr.exe -6 google.com                  # только IPv6
.\wtr.exe -r 192.168.1.254 | tee lan.txt # без TTY сам переходит на отчёт
```

## Режимы

| Режим | Запуск | Что делает |
|---|---|---|
| Интерактивный | по умолчанию | перерисовка таблицы, клавиши `q` `n` `a` `j` |
| Отчёт | `-r`, `--report` | одна таблица после всех циклов (по умолчанию 10) |
| JSON | `--json` | документ `wtr/1` после всех циклов |

Если стандартный вывод не консоль (перенаправление, `| tee`), интерактивный режим
бессмысленен — программа сама переходит на отчёт, как это делает `mtr`.

## Флаги

| Флаг | Значение |
|---|---|
| `-4`, `-6` | только IPv4 / только IPv6 (взаимоисключающие) |
| `-c`, `--cycles N` | число циклов; `0` = бесконечно (в TUI по умолчанию), в отчёте по умолчанию 10 |
| `-i`, `--interval DUR` | интервал между циклами (по умолчанию `1s`, минимум `100ms`) |
| `-t`, `--timeout DUR` | таймаут ответа на зонд (по умолчанию `5s`, минимум `100ms`) |
| `-m`, `--max-hops N` | максимум TTL (по умолчанию 30, диапазон 1..64) |
| `-q`, `--queries N` | зондов на хоп за цикл (1..16) |
| `-p`, `--psize N` | размер payload (14..65000 байт) |
| `-z N` | параллельные ICMP-хендлы (по умолчанию `max-hops*queries`, не больше 24; потолок 64) |
| `-B`, `--bind ADDR` | исходный адрес зондов |
| `-I`, `--interface X` | интерфейс: индекс (`17`) или имя (`Ethernet`, `Wi-Fi`) |
| `-n`, `--no-dns` | не резолвить обратные имена (DNS вообще не поднимается) |
| `-a`, `--aslookup` | запрашивать ASN через Team Cymru (TXT-запросы) |
| `-S`, `--dns-server H` | DNS-сервер для имён и ASN; порт `53` подставляется, если не указан |
| `-j`, `--jitter` | колонки `Jit`/`AvgJ`/`MxJ` вместо `StDev` |
| `-w`, `--wide` | широкая колонка хостов в отчёте (60 вместо 40) |
| `--version`, `-h`, `--help` | версия, справка |

Клавиши в TUI: `q` — выход, `n` — показать/скрыть имена, `a` — колонка `AS`
(значения ASN собираются только при запуске с `-a`), `j` — джиттер.

Коды возврата: `0` — успех (включая `--help`/`--version`), `1` — ошибка выполнения
(нет маршрута, не удалось открыть хендл), `2` — ошибка в аргументах.

## Как это работает без администратора

Единственный бэкенд — `iphlpapi.dll`: `IcmpSendEcho2` (IPv4) и `Icmp6SendEcho2`
(IPv6). Они работают из обычной учётной записи, в отличие от raw-сокетов
(`SOCK_RAW` + `IPPROTO_ICMP`), которым нужен администратор.

Эмпирически проверенные детали, на которых держится реализация (закреплены тестом
`internal/probe/layout_windows_test.go`):

* `IcmpSendEcho2` **сам меняет порядок октетов** в поле `Address` записи ответа:
  DWORD читается как little-endian, иначе `192.168.1.254` превращается в
  `254.1.168.192`, и ответы роутеров отбрасываются как чужие.
* В IPv6-буфере адрес ответившего начинается с 6-го байта, а `Status` и
  `RoundTripTime` читаются из смещений 28/32; если там нераспознанный код, а на
  26/30 известный — берётся вариант 26/30 (см. `parseV6StatusRTT`).
* RTT от API квантован 1 мс, поэтому для отображения берётся разница
  `QueryPerformanceCounter` до и после вызова (`internal/probe/clock_windows.go`).

Прочие решения, влияющие на точность:

* **Маркер зонда** (`WTR1` + цикл + TTL + номер) в payload. Сопоставить ответ с
  запросом в iphlpapi больше нечем, поэтому «запоздалые» ответы прошлого цикла
  отбраковываются и не портят статистику (см. колонку `Drop` и `stale_dropped`).
* **Микропауза 2 мс** между отправкой соседних TTL внутри цикла: без неё пачка
  зондов провоцирует ICMP rate-limit на роутерах, и потери на дальних хопах
  оказываются выше реальных.
* **Отдельный ICMP-хендл на воркера**: вызовы `IcmpSendEcho2` блокирующие, поэтому
  параллелизм достигается набором хендлов, а не горутинами поверх одного.
* **Асинхронный DNS**: движок только ставит адреса в очередь и читает кэш, так что
  резолвинг не тормозит цикл зондирования. Перед печатью итога очередь дожидается
  (не дольше 4 с) — иначе отчёт выходит с голыми адресами.
* **Длина маршрута** = минимальный TTL, с которого ответила цель в текущем цикле.
  Максимум брать нельзя: цель отвечает и на завышенных TTL, поэтому трассировка
  локального шлюза показывала бы 30 хопов вместо одного. Хопы за целью скрываются.
* **ECMP**: если на одном TTL отвечают несколько адресов, показывается самый
  частотный, остальные — отметкой ` +N`.

## Ограничения

* **Только ICMP-эхо.** `mtr --tcp/--udp` требует raw-сокетов, то есть администратора;
  цели, отвечающие только на TCP, этот бэкенд не видит.
* **Молчаливые роутеры.** Узлы, не отвечающие на ICMP (или отвечающие с
  rate-limit'ом), остаются `???` с потерями — это свойство сети, а не реализации.
* **ASN требует «правильный» DNS.** Домашние роутеры часто отклоняют TXT-запросы к
  `origin.asn.cymru.com` (`Query refused`), поэтому для `-a` нужен публичный
  resolver: `-a -S 8.8.8.8`.
* **Приватные адреса (RFC1918) в Team Cymru не резолвятся** — в колонке `AS` у
  локальных хопов будет `?`.
* **IPv6 привязан к интерфейсу** (нужен LUID из iphlpapi). Если IPv6 на хосте нет,
  `GetBestInterfaceEx` вернёт `ERROR_NETWORK_UNREACHABLE`, и программа честно
  сообщит, что маршрут не найден.
* RTT — время блокировки вызова iphlpapi, в него попадает планирование горутин; для
  LAN это доли миллисекунды, но значения чуть выше, чем у `tracert`.
* Не реализованы: `--split`/`--csv`, `--grpc`, перечисление интерфейсов (`--list`).

## Формат JSON

```json
{
  "schema": "wtr/1",
  "program": "wtr",
  "backend": "iphlpapi",
  "start": "2026-11-27T12:08:48+10:00",
  "duration_ms": 460.2,
  "cycles": 1,
  "reached_target": true,
  "target": {"name": "dns.google", "addr": "8.8.8.8", "family": "ipv4"},
  "interface": {"name": "Ethernet", "index": 17},
  "hops": [{
    "ttl": 3,
    "addrs": ["178.218.106.76"],
    "names": ["178.218.106.76-static.dsl-online.example.net"],
    "asns": ["AS49350"],
    "flags": ["!H"],
    "status": 11013,
    "status_name": "IP_TTL_EXPIRED_TRANSIT",
    "pending": false,
    "stats": {"sent": 2, "lost": 0, "loss_pct": 0, "last_ms": 1.9, "avg_ms": 1.9,
               "best_ms": 1.7, "worst_ms": 2.1, "stdev_ms": 0.3,
               "jitter_last_ms": 0, "jitter_avg_ms": 0.1, "jitter_max_ms": 0.2}
  }],
  "stale_dropped": 0
}
```

`pending: true` означает, что на этом TTL ещё не было ни одного ответа (в таблице
такой хоп показывается прочерками). `flags` — отметки mtr-стиля: `!H` хост недоступен,
`!N` сеть недоступна, `!X` порт недоступен, `!?` прочая ошибка.

## Структура проекта

```
cmd/wtr              точка входа
internal/cli         разбор аргументов, выбор режима, цикл вывода
internal/trace       движок: растущий TTL, воркеры, агрегация, снимки состояния
internal/probe       iphlpapi: хендлы, раскладки структур, коды статусов
internal/stats       накопитель статистики хопа (Велфорд, джиттер RFC 3393)
internal/dnsx        асинхронные PTR и ASN (Team Cymru)
internal/render      TUI-таблица, отчёт, JSON
internal/console     VT-режим консоли, размер окна, чтение клавиш
```

## Тесты

```powershell
go test .\cmd\... .\internal\...
```

Что проверяется без сети: раскладки и порядок байтов iphlpapi, коды статусов и
отбраковка «запоздалых» ответов, маркер зонда, формула стандартного отклонения и
агрегация джиттера, поведение движка (достижение цели, отсечка хопов за целью,
учёт потерь и stale-ответов), разбор аргументов, нормализация `--dns-server`,
форматирование таблиц, отчёта, JSON и имён Team Cymru.

Проверено на живой сети (Windows 11, провайдер МТС): IPv4 в интернет (13 хопов до
`8.8.8.8`), локальный шлюз (1 хоп), недоступная цель (`192.0.2.1` — потери без
ложного «достигнуто»), режимы TUI/отчёт/JSON, имена и ASN через `-S 8.8.8.8`,
переход в отчётный режим при перенаправлении вывода, коды возврата.

**Не** проверено на живой сети: IPv6 (на тестовой машине не было связности —
реализация опирается на проверенные раскладки и `Icmp6SendEcho2`), обработка
`Ctrl+C` в TUI (не воспроизводится в неинтерактивной сессии), `--bind` на
многосетевых машинах.

Флаг `-race` требует `cgo` (`CGO_ENABLED=1` и C-компилятор); без него конкурентность
держится на мьютексах движка и проверяется тестами движка.
